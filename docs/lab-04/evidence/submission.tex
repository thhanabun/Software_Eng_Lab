\section*{Answer Part 2: Spec DD (5 pts)}
% =====================================================================

\textbf{Link:} \href{https://github.com/thhanabun/Software\_Eng\_Lab/blob/main/docs/lab-04/specification.md}{docs/lab-04/specification.md}
Approved as PR \#59 \textbf{before} any implementation PR; 7 reviewer follow-ups folded in.

\subsection*{Locked decisions}
\begin{itemize}
\item Minimal action model per sheet \S8.3: list/create/view-edit only, no assignee/status on actions; fields date/time (auto), description, result, performer (auto), follow-up flag + mandatory note, attachment notes.
\item Resolution gate: \code{* -> RESOLVED} requires $\geq$1 action (BR-10), staff/admin only, backend-enforced.
\item Optimistic concurrency via ticket \code{updatedAt}: mismatch $\to$ 409; required on action-edit, checked-when-present elsewhere (Lab 3 compat); 409 is best-effort usability, not a security boundary.
\item Requesters see all actions on owned tickets, read-only.
\item Dashboards per handout examples with per-count drill-downs (BR-16); admin reuses staff dashboard + user counts.
\end{itemize}

\subsection*{Requirements and rules (summary)}
FR-01--FR-04 actions CRUD semantics; FR-05--FR-08 workflow, gate, concurrency, advisory
indication; FR-09--FR-11 dashboards; FR-12--FR-13 regression and hardening.
BR-01--BR-08 actions; BR-09 final 8-status matrix (Lab 3 matrix retained); BR-10 gate;
BR-11 concurrency; BR-12 CANCELLED freeze; BR-13 unassign coupling carryover; BR-14--BR-16
dashboard calculations; BR-17 safe errors; BR-18 regression gate.
